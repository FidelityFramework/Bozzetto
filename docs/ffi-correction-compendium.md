# The FFI correction: standing record

Consolidated on 2026-10-11 from the twenty-one dated records listed in section 15, which it replaces. Those records stay readable in history (`git show d1c60aac:docs/<name>`). From here on this file is maintained in place: a change to the work changes this record, not a new dated file. The one-page handoff format and the auditor's binding review are in [development.md](development.md); this record holds what the handoffs settled.

Words used here. A **ruling** is the owner's or the spec's decision and binds every component. **Landed** means committed on `main`. **Accepted** means the sole auditor’s verdict against the declared, bound evidence scope, with its decision on whether full regression is earned (§3). **In force** means nobody has superseded it. **Open** means nobody has done or decided it. Every commit named here resolved in its repository on 2026-10-11 (`git cat-file -t`). Nothing else was re-executed for the consolidation, so every count and gate line is the record's own, graded as the record graded it. Line numbers hold at the heads named beside them and must be re-located by content anywhere else.

## 1. Purpose and status

The owner's framing (2026-10-11): "FFI is a multi-project initiative - affecting Clef, Composer and Farscape. That means all other related projects - Alex, Fidelity.PSG, Fidelity.FSharp.Incremental and of course the tooling Clef Auto Complete, Lattice, and Bozzetto. This is about marshaling to the C/Cpp boundary with proofs as part of the hypergraph that allows the differential compilation to proceed with confidence."

So the purpose is this. Every value that crosses the C or C++ boundary carries a contract that Baker settles, that Fidelity.PSG publishes as rows of the hypergraph, that Alex witnesses and that the target pathway realizes. Those proofs are what let Composer recompile only what a change affects and trust what it keeps. The governing principle from the rulings record: every native callable retains an authoritative boundary contract; Baker establishes compatibility, the PSG preserves the evidence, Alex witnesses the settled operation, the target pathway realizes it. Nothing is deferred to Alex and nothing missing is invented.

The owner's direction for the tooling (2026-10-11): "Clef Auto Complete will need to be as sensitive to graph changes as any part of the CCS framework as that's the place where re-evaluation in design time is most performance dependent. We haven't touched it much but I expect it to use both Ranvier and Fidelity.FSharp.Incremental which should pervade all these tools like we just did for Bozzetto to make a fully reactive toolchain with differential compilation by default."

## 3. Authority and working rules

- **Authority order.** Owner rulings, then the spec, then code and executed evidence, then agent reports. Where the spec is silent, the clarification lands in clef-lang-spec before the compiler change. Owner feedback (2026-10-11): sweep the spec and read around the hits before asking.
- **Evidence grades**, as the requirement map and every return use them: [X] executed at the pinned head; [C*] re-read at the head; [C] cited; [S] spec text at a named commit; [H] header; [L] live; [A] agent report; [D] documentation; [I] inference. An executed unfiltered result outranks code read at a pin, which outranks spec text, which outranks an agent's report. Every return states how it knows.
- **Test defects.** A test is called defective only when the spec shows it wrong, with the clause quoted (Phase 0 audit). Blanket test rewrites, for example modulo rewrites of finite counters, are rejected. Where the Phase 0 audit checked a triage group against source and spec, its finding supersedes the triage verdict.
- **Validation per increment** (owner direction, 2026-10-11). The implementer runs focused suites for the changed owner and its direct consumers, the source shape matrix and one mutant per new rule before handoff. The sole auditor decides whether full regression is earned, recording the risk, exact scope and expected wall-clock cost before dispatch. No full sweep runs automatically per increment. Record filters, actual elapsed time and the evidence scope; a narrowed run remains narrowed. Every selected gate is leased for the whole run and released, with its actual ledger line pasted verbatim. For gates carrying the historical baseline comparison, retain the form: `<suite> total=N passed=N failed=N skipped=0 | vs trusted: missing=0 added=N new-failures=0 resolved=N`. The name-by-name comparison is authoritative within the same declared selection, not totals or an assumed whole-suite scope. Historical unfiltered results and accepted counts remain unchanged. Binding: a source manifest with full commit and tree identities, blob hashes and changed paths against the previously accepted heads, plus artifact hashes, built with `--no-restore --disable-build-servers -m:1 -t:Rebuild`. Artifacts are hashed from a build of the committed head, because rebuilt binaries embed the commit hash in their informational version and pre-commit hashes never verify. The generalized form is [development.md](development.md), "One-page increment handoff"; the FFI template that carried it is retired.
- **Gate validity.** No source in a running gate's dependency closure changes during the gate. Work that edits the same file, `RangeAnalysis.fs` in particular, is serialized, and one gate runs after all edits stop.
- **Lease coverage.** The October 3 NativeCallbacks and regression runs overran their leases by eight and nine minutes (P0-12) and are historical observations only. Every later gate ran inside a held whole-run lease; `scripts/work-lease run` renews while its command runs. One stable holder per agent and project; a deferred ask stays queued while its caller retries, a caller that gives up withdraws it, and an ask nobody retries within two minutes is reaped.
- **Composer baseline commands** live in the evidence root (`t0/baseline/test-all.sh`, logs under `t0/baseline/logs/`), not in a per-repository record (P0-14).
- **Retrieval first.** On resume obtain a fresh schema and rediscover seeds for the pushed heads, then pinned `find`, `pgq` and `sources`. Never reuse an older snapshot as current; the notch's later indexing windows were explicitly stale.
- **Delegation authority** (owner direction, 2026-10-11). The implementer is authorized to coordinate agents and carry out settled implementation work, including routine delegation, without asking again. LAN agents provide bounded first-pass reading and query preparation; local design reviews support implementation. These roles do not supply acceptance verdicts or settle outstanding owner policy.
- **Audit before every commit or swap** (owner rule, updated 2026-10-11). Claude Code running Opus 5.5 is the sole auditor, using native Claude Code rather than a Pi model substitution. Record its actual model, run identity, verdict and available usage on the Agent Work board and in the handoff. The auditor determines the earned full-regression scope under the validation rule above. Blocking findings are acted on; a reject means iterate. A brief generated from stale text is a void pass and is recorded as such.
- **Terminology.** Composer is a differential compiler; "incremental" is reserved for Fidelity.FSharp.Incremental. Builds and suites over Clef and Composer code are Composer work: they run under leases and show on the Composer page.

### 4.3 Rulings of the October 10 and 11 increments

- **Opaque alternatives** stay unobservable and refuse only where a reachable integer is committed: CCS8011 at the binding that names the payload, once per enclosing binding. The first draft of this ruling published `Empty` for an opaque alternative; width-inference.md:78 forbids substituting a known range for a missing observation, so the draft was revised after the Lemonade adversarial review, and its "joins as Empty under proof" sentence was struck after Sol finding 6. An opaque alternative joins as `Unbounded` whether or not the body is active (`r4-six-ruling.md`). Two recorded deviations from the written ruling: the sequence twin drives a resolved origin with an unobservable element, since an unresolved origin cannot be reached from an entry; the uninvoked loop fixture owes no `MissingBound` residual because the loop-range recipe runs only for committed cells (`RangeAnalysis.fs:2982`), so its twin asserts that.
- **Inactive-implementation exclusion follows execution ownership through nested owners**: a self-owning sequence generator or closure continues at its unique structural parent, so an uninvoked body commits no integer (width-inference.md:78, :80; clef e8d54312, `OrdinaryDemand.fs:243-255`).
- **`NativeDefault.zeroed` of an integer kind is the point 0**, tabled in `RangeSources.intrinsic`; the row applies only to integer, boolean and char nodes, which is all that transfer ranges (`RangeAnalysis.fs:2163-2176`; clef d2e6cf64).
- **`BorrowedView.length` has one owner**, `BorrowedViews.numericBoundary` (`BorrowedViews.fs:95-101`). The intrinsic row that duplicated it was withdrawn at clef b0ef172d after the executed mutant left a platform-aware positive control passing.
- **Resource obligations remain inside receiving contracts** (FFI §3.6 item 2, `ffi-boundary.md:250-255`). "Foreign resource contract" and "proof evidence" are not spec terms.
- **Phase B question numbering**: the Oct 11 set Q1 to Q6 (section 7) is a different set from the rulings record's "ruling Q1" (compiler-owned entries, R1) and from the research gap map's Q4, Q5, Q7 and Q13.
